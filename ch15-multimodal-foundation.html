多模態 Foundation Models

影像 + 文字 + 報告 + EHR + 訊號——醫療 AI 進入「同時看與說」的時代。

Image + text + report + EHR + signal — medical AI in the era of "seeing & speaking together."

為什麼多模態

醫療診斷天生是多模態的

胸 X 光 + 病史 + 抽血 + 心電圖 + 生命徵象——沒有醫生只看單一資料下診斷。但 2020 年前的醫療 AI 多半「單模態」，每個模型只專一資料。多模態 Foundation Model 透過共同的嵌入空間，把不同模態接到同一個語意層，從而：

  • 用影像 + 報告做零樣本分類（CLIP-style）。
  • Zero-shot classification from image + report (CLIP-style).
  • 由影像直接生成放射報告草稿。
  • Generate radiology report drafts directly from images.
  • 跨模態檢索：以症狀文字找相似影像、以影像找相似病歷。
  • Cross-modal retrieval: text symptoms → similar images, image → similar charts.
  • VQA（Visual Question Answering）：醫生口述問題，AI 對影像作答。
  • VQA: clinician asks in natural language, AI answers about the image.

架構模式

三種主流結合方式

① Late fusion (CLIP-style)

各模態各自 encoder → 同維度向量 → cosine 對齊。優點：簡單、易加新模態；缺點：早期細節對齊弱。

Per-modal encoders → same-dim vectors → cosine alignment. Pros: simple, easy to add modalities. Cons: weak early alignment.

② Cross-attention

用 cross-attention 把一模態的 query 注入另一模態（如 LLaVA-Med 把影像 token 注入 LLM）。

Cross-attention queries one modality from another (e.g., LLaVA-Med injects image tokens into the LLM).

③ Token-mixed

把所有模態 token 化後丟同一 Transformer。Med-Gemini、ESM-3 用這個範式。

Tokenize all modalities into one Transformer. Used by Med-Gemini, ESM-3.

實作

BiomedCLIP 跨模零樣本

from open_clip import create_model_from_pretrained, get_tokenizer
from PIL import Image
import torch
m, prep = create_model_from_pretrained("hf-hub:microsoft/BiomedCLIP-PubMedBERT_256-vit_base_patch16_224")
tok = get_tokenizer("hf-hub:microsoft/BiomedCLIP-PubMedBERT_256-vit_base_patch16_224")
img = prep(Image.open("chest_xray.png")).unsqueeze(0)
labels = ["pneumonia", "normal", "effusion", "pneumothorax"]
texts = tok(["this is a chest x-ray showing "+l for l in labels])
with torch.no_grad():
    img_feat = m.encode_image(img); txt_feat = m.encode_text(texts)
    img_feat = img_feat / img_feat.norm(dim=-1, keepdim=True)
    txt_feat = txt_feat / txt_feat.norm(dim=-1, keepdim=True)
    sim = (100.0 * img_feat @ txt_feat.T).softmax(-1)
for l, p in zip(labels, sim[0]): print(l, round(p.item(),3))
library(reticulate); library(magick)
open_clip <- import("open_clip"); torch <- import("torch")
ck <- "hf-hub:microsoft/BiomedCLIP-PubMedBERT_256-vit_base_patch16_224"
out <- open_clip$create_model_from_pretrained(ck)
m   <- out[[1]]; prep <- out[[2]]
tok <- open_clip$get_tokenizer(ck)
img <- prep(magick::image_read("chest_xray.png"))$unsqueeze(0L)
labels <- c("pneumonia","normal","effusion","pneumothorax")
texts  <- tok(paste("this is a chest x-ray showing", labels))

本章小測 (3 題)

1. CLIP-style late fusion 最大優勢？

1. The biggest advantage of CLIP-style late fusion?

A. 易加新模態、零樣本分類A. Easy to add modalities, zero-shot classification
B. 早期細節對齊最強B. Strongest early alignment
C. 不需要對比學習
D. 不需要 GPU
A 正解。缺點是早期細節對齊較弱。A. Downside: weaker fine-grained alignment.

2. Med-Gemini 屬於哪種整合範式？

2. Med-Gemini follows which integration paradigm?

A. Late fusion
B. Cross-attention only
C. Token-mixed（多模 token 一起進 Transformer）C. Token-mixed (all-modal tokens into one Transformer)
D. Late ensemble
C 正解。Gemini 系列原生支持 token-mixed。C. Gemini family natively supports token-mixing.

3. 為什麼影像-文字檢索可以做「零樣本分類」？

3. Why can image-text retrieval do "zero-shot classification"?

A. 把每個類別包裝成 prompt 文字，計算與圖的相似度A. Wrap each class as a prompt sentence, compare similarity to the image
B. 模型本來就有所有類別
C. 它記憶了訓練資料
D. 隨機猜的
A 正解。CLIP 的關鍵設計。A. The core CLIP trick.
