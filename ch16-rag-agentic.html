BLOCK D · CHAPTER 16 / 20

醫學 RAG 與 Agentic AI

MedRAG、i-MedRAG、MedAgents、MIRAGE benchmark——把 LLM 變成可靠醫療助理的關鍵。

MedRAG, i-MedRAG, MedAgents, MIRAGE benchmark — what makes LLMs trustworthy medical assistants.

新手友善 中階 進階補充

這一章你會學到什麼？

不管你是想用 LLM 卻怕幻覺的臨床研究者、剛聽到 MCP的工程師，或想做醫療助理產品的創業者：

  • 串起 RAG 的 indexing → retrieval → re-rank → generate → verify → iterate 六段管線
  • 分辨 BM25 / dense / hybrid retrieval 三種方法
  • 讀懂 MIRAGE (7663 問題) / i-MedRAG / MedAgents benchmark 結果
  • 避開「RAG 消除幻覺」「context 越多越好」迷思

For clinicians wanting LLMs but fearing hallucination, engineers new to MCP, or medical-assistant founders:

  • Chain RAG's 6-step pipeline: indexing → retrieval → re-rank → generate → verify → iterate
  • Differentiate BM25 / dense / hybrid retrieval
  • Read MIRAGE (7,663 questions) / i-MedRAG / MedAgents benchmarks
  • Steer clear of "RAG eliminates hallucination" and "more context is better" myths
動機

LLM 知道的不夠，而且會幻覺

LLM 的兩大臨床罩門：(1) 知識截止——預訓資料有日期，新指引 / 新藥 / 新試驗一律未知；(2) 幻覺——會編造 PubMed 編號、編造劑量。RAG (Retrieval-Augmented Generation) 解法：每次提問先到外部知識庫（PubMed、UpToDate、ICD、formulary）檢索相關段落，再讓 LLM 在這些段落基礎上回答。

2024 起，RAG 與 Agentic AI 結合：LLM 主動規劃多次檢索、調用工具（計算機、SNOMED、藥物資料庫），把多步推理拆成可驗證的小步——這就是 MedAgents / i-MedRAG 的核心想法。

benchmark

MIRAGE：第一個大型醫療 RAG benchmark

2024 ACL Findings, Xiong et al. MIRAGE 包含 7,663 個來自 5 大醫療 QA 資料集的問題；同時推出 MedRAG toolkit，跨 41 種 corpus × retriever × LLM 組合做 1.8T token 大規模實驗。重要發現：

  • MedRAG 把 6 種 LLM 在 MedQA 提升 達 18%。
  • MedRAG boosts six LLMs on MedQA by up to 18%.
  • GPT-3.5 + MedRAG 接近 GPT-4 級別，Mixtral 同理。
  • GPT-3.5 / Mixtral + MedRAG approach GPT-4 levels.
  • 出現「log-linear scaling」與「lost-in-the-middle」效應——retrieve 太多反而退步。
  • "Log-linear scaling" + "lost-in-the-middle" effects emerge — retrieving too much hurts.
  • i-MedRAG（迭代追問）讓 GPT-3.5 在 MedQA 達 69.68%，勝過所有 prompt-engineering 與 fine-tune 法。
  • i-MedRAG (iterative follow-up) reaches 69.68% on MedQA with GPT-3.5 — beating all prompt engineering & fine-tuning.
架構

標準六段管線

索引建構

把 PubMed / UpToDate / 藥典切成 chunks，用 BiomedBERT / BGE-M3 嵌入後存進向量資料庫（Faiss / Milvus / Qdrant）。

Chunk PubMed / UpToDate / formulary; embed with BiomedBERT / BGE-M3; store in vector DB (Faiss / Milvus / Qdrant).

檢索

使用者 query → embed → top-k 段落。混合 BM25 + dense 通常勝過任一單獨方法。

Query → embed → top-k chunks. Hybrid BM25 + dense usually beats either alone.

重排序

用 cross-encoder（如 BGE-reranker）精篩 top-20 → top-5。

Use cross-encoder (e.g., BGE-reranker) to refine top-20 → top-5.

提示與生成

把片段塞進 prompt，要求 LLM 引用片段編號。

Inject snippets, require the LLM to cite snippet IDs.

自我審核 / 引用檢查

第二輪 LLM 檢查答案的每個 claim 是否確實對應到引用段落（claim-evidence alignment）。

Second LLM pass to verify every claim aligns with cited evidence.

迭代追問

若答案信心不足，LLM 自動生成 follow-up 問題，回到 step 2 再來一輪。

If confidence is low, LLM generates follow-ups and re-enters step 2.

Agentic AI

MedAgents：多代理協作

MedAgents 框架把醫療 QA 看成「多專家會診」：一個 LLM 扮演心臟科、一個扮演影像科、一個扮演藥師，彼此交換 evidence 與意見，最後由「主治醫師」整合。實驗顯示 MedAgents 在 MedQA、MedMCQA 上的多選題表現可顯著超越 single-LLM CoT。

更進階的設計是 tool-using agents：模型可以呼叫計算機（藥物劑量、eGFR）、查 Drugs.com、查臨床試驗、查 ICD/SNOMED 對應、執行 SQL on FHIR。LangGraph / OpenAI Assistants v2 / Anthropic MCP 是 2024-2026 主流框架。

MedAgents reframes medical QA as a "multi-specialist consult": one LLM plays cardiology, another radiology, another pharmacy; they exchange evidence and a "primary physician" synthesizes. Reported to significantly outperform single-LLM CoT on MedQA / MedMCQA.

More advanced: tool-using agents — the model invokes calculators (dosing, eGFR), Drugs.com, clinical-trial lookup, ICD/SNOMED mapping, SQL on FHIR. LangGraph / OpenAI Assistants v2 / Anthropic MCP are dominant frameworks 2024–2026.

實作

最小 MedRAG

# pip install langchain langchain-community faiss-cpu sentence-transformers
from langchain_community.embeddings import HuggingFaceEmbeddings
from langchain_community.vectorstores import FAISS
from langchain_community.document_loaders import TextLoader
from langchain.text_splitter import RecursiveCharacterTextSplitter
docs = TextLoader("pubmed_chunks.txt").load()
chunks = RecursiveCharacterTextSplitter(chunk_size=400, chunk_overlap=40).split_documents(docs)
emb = HuggingFaceEmbeddings(model_name="BAAI/bge-m3")
db  = FAISS.from_documents(chunks, emb)
q = "What's the first-line therapy for HER2+ metastatic breast cancer in 2024?"
hits = db.similarity_search(q, k=5)
for h in hits: print(h.page_content[:200])
# Feed into your favorite LLM with prompt:
# "Answer using only the following snippets... Cite [1], [2]..."
library(reticulate)
lc <- import("langchain_community"); lcs <- import("langchain.text_splitter")
docs <- lc$document_loaders$TextLoader("pubmed_chunks.txt")$load()
splitter <- lcs$RecursiveCharacterTextSplitter(chunk_size=400L, chunk_overlap=40L)
chunks <- splitter$split_documents(docs)
emb <- lc$embeddings$HuggingFaceEmbeddings(model_name="BAAI/bge-m3")
db <- lc$vectorstores$FAISS$from_documents(chunks, emb)
hits <- db$similarity_search("HER2+ MBC first-line 2024", k=5L)

案例故事
2024 · Stanford OpenEvidence

OpenEvidence：規模化臨床 RAG

OpenEvidence (Stanford spin-off, 2024) 是一個免費臨床決策支援工具——醫師輸入問題（如「78 歲 ER+ HER2- 乳癌患者 NACT 該選哪個 regimen?」），系統 24/7 回應，並附 PubMed 引用。

內部架構：(1) 索引 PubMed + UpToDate + NCCN guidelines + ClinicalTrials.gov 約 3500 萬筆；(2) Hybrid retrieval（BM25 + dense BGE-M3）；(3) cross-encoder re-rank；(4) GPT-4o 生成答案，要求每個 claim 引用具體 PMID；(5) 後處理 verifier 檢查引用有效性。

2024 年底成果：(1) 已有 20 萬+ 醫師使用；(2) 平均回應時間 12 秒；(3) JAMA 對照研究顯示比 Google Search 提供更精確且引用率高的臨床答案（86% vs 32% 可追溯）。

但仍有限制：(1) 對「未在 PubMed 索引」的最新指引（如剛發布的 ASCO 2024）反應慢；(2) 對跨族裔特異性問題（亞洲乳癌特殊 HER2 突變模式）回答仍 western-centric；(3) 罕病問題覆蓋率僅 ~60%。

OpenEvidence (Stanford spin-off, 2024) is a free clinical decision-support tool — clinicians type questions (e.g., "78 yo ER+ HER2- breast cancer, NACT regimen?"), system answers 24/7 with PubMed citations.

Architecture: (1) indexes ~35M items across PubMed + UpToDate + NCCN guidelines + ClinicalTrials.gov; (2) hybrid retrieval (BM25 + dense BGE-M3); (3) cross-encoder re-rank; (4) GPT-4o generates answers with PMID citation per claim; (5) verifier post-processing checks citation validity.

By end-2024: (1) 200K+ clinicians using it; (2) avg response 12 seconds; (3) JAMA comparison study showed more accurate and citation-rich clinical answers than Google Search (86% vs 32% traceable).

Limits remain: (1) slow on guidelines not yet PubMed-indexed (e.g., fresh ASCO 2024 releases); (2) cross-ancestry specific questions (Asian breast cancer HER2 mutation patterns) still western-centric; (3) rare-disease coverage only ~60%.

教訓：規模化臨床 RAG 已成現實，但「最新 + 跨族裔 + 罕病」仍是當前邊界。
Lesson: scaled clinical RAG is reality, but "latest + cross-ancestry + rare disease" remain frontiers.

想得更深

Q1. RAG 能完全消除幻覺嗎？不能。MIRAGE 顯示 i-MedRAG 雖達 69.68%，仍有 30% 錯誤。RAG 把幻覺從「無中生有」變成「引用錯誤」，仍需人工驗證。解法：claim-evidence alignment 自動 verifier，OpenEvidence 採此。
Q1. Can RAG fully eliminate hallucination?No. MIRAGE shows i-MedRAG hits 69.68% but 30% still errs. RAG turns "fabrication" into "misquote"; manual verification still needed.Fix: claim-evidence alignment verifiers — OpenEvidence uses this.
Q2. 為什麼 hybrid retrieval 通常勝過單一方法？BM25 對「精確關鍵字」強（藥名、ICD code、變異 HGVS）；dense 對「語意相似」強（症狀描述、概念）。臨床問題常兩者皆有，hybrid 取長補短。調 BM25:dense 權重通常 0.3:0.7 起步。
Q2. Why does hybrid retrieval usually win?BM25 excels at "exact keyword" (drug names, ICD codes, HGVS variants); dense excels at "semantic similarity" (symptom descriptions, concepts). Clinical questions blend both — hybrid combines strengths.Tune BM25:dense weight; 0.3:0.7 is a good start.
Q3. MCP 會如何改變醫療 AI 部署？2024 Anthropic 推出 MCP 統一 agent-tool 通訊。預期：醫療資訊系統（EMR、PACS、藥典）會逐漸提供 MCP server；agent 透過 MCP 就能整合 retrieval + tool use。瓶頸：醫療資料隱私導致 on-premise MCP server 是主流。
Q3. How will MCP change medical AI deployment?Anthropic launched MCP in 2024 to unify agent-tool comms. Expect medical info systems (EMR, PACS, formularies) to expose MCP servers progressively; agents can then integrate retrieval + tool use.Bottleneck: medical privacy mandates on-premise MCP servers.
Q4. 醫療 agent 的自主性邊界在哪？三層光譜：(1) read-only retrieval（只查詢）—FDA 不視為醫材；(2) draft assistant（草擬報告）—Class II SaMD；(3) autonomous decision（自主下處方）—Class III + 嚴格臨床試驗。當前部署多停留在 (1)、(2)，(3) 在 2030 前不太可能。
Q4. Where's the autonomy boundary for medical agents?Three-tier spectrum: (1) read-only retrieval — FDA doesn't consider it a device; (2) draft assistant — Class II SaMD; (3) autonomous decision — Class III + strict trials.Most deployments stay at (1) & (2); (3) is unlikely before 2030.
