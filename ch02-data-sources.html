生醫資料的四象限

把生醫大數據概念化的最快方法，是放在「分子 ↔ 個體」與「研究用 ↔ 臨床用」兩個軸上。每個象限的取得管道、隱私限制與適用模型都不同。

The fastest way to conceptualize biomedical big data is along two axes: "molecular ↔ individual" and "research ↔ clinical." Each quadrant differs in access, privacy and best-fit models.

申請到分析：四步驟

權限申請與 IRB

UK Biobank / All of Us / dbGaP 都需要 IRB 通過、研究計畫書與資料安全聲明。預留 2–4 個月。

UK Biobank, All of Us, dbGaP all require IRB approval, a research protocol, and a data security plan. Budget 2–4 months.

標準化與品質檢查

EHR → OMOP CDM / FHIR；影像 → 重採樣與 z-score；基因體 → GATK best practice + lift-over。記得跑 Outlier、Missingness、Cohort drift。

EHR → OMOP CDM / FHIR; imaging → resample + z-score; genomics → GATK best practice + lift-over. Always run outlier, missingness, cohort drift checks.

可重現環境與版本管理

用 Docker / Singularity 鎖環境；用 DVC / lakeFS / Pachyderm 追資料版本；Git LFS 不夠用。

Lock environments with Docker/Singularity; track data versions with DVC/lakeFS/Pachyderm; Git LFS is not enough.

去識別化與最小必要

HIPAA Safe Harbor 18 項識別子刪除；採資料最小化原則；高敏資料留在 enclave / TRE 不下載。

Remove the 18 HIPAA Safe Harbor identifiers; apply data minimization; keep sensitive data in enclaves / TREs without download.

想再深一點？OMOP vs FHIR vs HL7 的歷史與工程取捨

同一份病歷，三種命運

HL7 v2（1989–）是「傳訊用」格式，pipe-delimited 純文字（MSH|^~\&|...），仍是 90% 美國醫院內部訊息傳遞的事實標準。設計重點：低頻寬、跨廠商互通。缺點：難讀、難擴充、版本碎裂（v2.3、v2.4、v2.5、v2.8 互不相容）。

FHIR (Fast Healthcare Interoperability Resources, 2014–)是 HL7 第四代，借鏡 REST + JSON。Patient, Observation, Condition, MedicationRequest 等資源以 URI 對應，可由瀏覽器直接讀。2024 USCDI v4 + CMS Rule 9115-F 強制美國 EHR 廠商提供 FHIR API，這是「外部開發者可即時拉病歷」的關鍵轉折。

OMOP CDM (Common Data Model, OHDSI, 2009–)是「分析用」schema：固定 39 張表（Person、Visit、Drug_Exposure、Condition_Occurrence ...），所有概念對應到 OMOP Vocabulary（基於 SNOMED CT、RxNorm、LOINC）。OHDSI 全球聯盟在 OMOP 上跑同一套 SQL，2024 已有 800M+ 患者橫跨 70+ 國，做「分散式聯邦研究」（不送資料、只送程式）。

工程取捨：

  • 即時臨床決策支援 (CDS)：用 FHIR（API 即時、低延遲）
  • 跨機構流行病學 / 藥物警示：用 OMOP（標準術語、可比性高）
  • 醫院內部 ADT / lab 訊息：HL7 v2（仍是現實）
  • 多模態 ML 訓練：通常先 FHIR 收集 → ETL 到 OMOP → 再展平成 ML 特徵表（如 MIMIC-OMOP）

新興方向：FHIR-CDM hybrid（Cerner / Epic 都在做）、以及 OMOP CDM v6.0 加入 genomics 表（2024 試行版）。

HL7 v2 (1989–) is a messaging format: pipe-delimited plain text (MSH|^~\&|...), still the de-facto standard for 90% of internal US hospital messaging. Designed for low bandwidth + vendor interop. Downside: hard to read/extend, fragmented (v2.3 / v2.4 / v2.5 / v2.8 mutually incompatible).

FHIR (2014–) is HL7's 4th-gen approach, borrowing REST + JSON. Patient, Observation, Condition, MedicationRequest map to URIs readable in any browser. 2024 USCDI v4 + CMS Rule 9115-F mandate FHIR APIs from US EHR vendors — the pivot point for real-time external access.

OMOP CDM (2009–) is an analytics schema: 39 fixed tables (Person, Visit, Drug_Exposure, Condition_Occurrence...) where every concept maps to the OMOP Vocabulary (SNOMED CT, RxNorm, LOINC). OHDSI runs identical SQL across 800M+ patients in 70+ countries — federated research (ship code, not data).

Tradeoffs:

  • Real-time CDS: FHIR (API-first, low latency)
  • Cross-institution epidemiology / pharmacovigilance: OMOP (standardized vocab, high comparability)
  • In-hospital ADT/lab messaging: HL7 v2 (reality on the ground)
  • Multimodal ML training: usually FHIR ingest → ETL to OMOP → flatten to ML feature tables (e.g., MIMIC-OMOP)

Emerging: FHIR-CDM hybrid (Cerner, Epic), and OMOP CDM v6.0 with genomics tables (2024 pilot).

案例故事

兩個影響你資料策略的故事

2023-06 → 2023-10 · UK Biobank 申請實錄

一個博士後等了 4 個月的 UK Biobank 申請

Sarah 是劍橋大學的心血管流行病學博士後，2023 年 6 月想做「WGS + 影像 + EHR 整合預測心房顫動」的研究。她以為按下「Apply」就能拿資料——實際流程是：

  1. Week 1：機構簽署 MTA（Material Transfer Agreement），需要學校法務批核（5–10 工作天）
  2. Week 2–3：撰寫 Research Application Form，包含科學摘要、Lay summary（給民眾看的白話版本）、資料安全聲明、預計分析方法
  3. Week 4：UKB AAC（Access Approval Committee）初審——這次被 reject 一次，理由是「lay summary 太技術，民眾看不懂」
  4. Week 6：重新提交，AAC 排隊到 Week 10
  5. Week 12：通過，繳費 £6,000（fee tier 取決於資料模態與商業用途）
  6. Week 14：在 UKB-RAP（DNAnexus 雲端）開帳號，IT 部門 SSO 整合
  7. Week 16：拿到 read-only access——所有分析必須在 RAP enclave 內進行，不能下載原始資料

整整 4 個月。Sarah 的 PI 笑她：「你以為這是 Kaggle 嗎？」她回應：「我以為這是 GitHub。」其實兩者都不是——這是受託資料治理（Trusted Research Environment, TRE）的時代。

她學到什麼？（1）IRB 與資料申請並行（不要等 IRB 過才申請資料）；（2）Lay summary 要請非科學家朋友讀過；（3）預算要含 fee + 雲端運算費（RAP 上跑 PLINK GWAS 約 £200–£800/次）；（4）計畫期限要含「等待期」，否則 grant 結束資料還沒到手。

Sarah, a cardiovascular-epi postdoc at Cambridge, started a "WGS + imaging + EHR integration for AFib prediction" project in June 2023. She thought pressing "Apply" would give her data — actual process:

  1. Week 1: Institutional MTA (Material Transfer Agreement), 5–10 business days via legal office
  2. Weeks 2–3: Research Application Form — science abstract, lay summary, data-security statement, planned methods
  3. Week 4: UKB AAC first review — rejected once: "lay summary too technical, public can't read it"
  4. Week 6: Resubmission, queued to Week 10
  5. Week 12: Approved, £6,000 fee (tier depends on modalities + commercial use)
  6. Week 14: UKB-RAP (DNAnexus cloud) account, SSO via IT
  7. Week 16: Read-only access — all analysis inside RAP enclave, no raw download

Four months. Her PI joked, "You thought this was Kaggle?" She replied, "I thought it was GitHub." Neither — this is the era of Trusted Research Environments.

Lessons: (1) submit IRB and data application in parallel; (2) have a non-scientist read your lay summary; (3) budget = fee + cloud compute (PLINK GWAS on RAP ≈ £200–£800/run); (4) build the wait into your timeline, else your grant ends without data.

教訓：在 TRE 時代，「擁有資料」這四個字已經過時——你「拜訪」資料，而不是「擁有」資料。
Lesson: in the TRE era, "owning data" is obsolete — you visit data, not own it.
2018 · MIMIC-III 救活的研究

MIMIC-IV 救活的研究：sepsis 早期預測

2018 年 Henry 等人在 Sci Transl Med 發表 TREWScore，宣稱能比 SIRS 提早 28 小時預測 sepsis。但模型訓練在「單一醫院 5 年資料」，外部驗證從未做過。

同年 Beth Israel 公開 MIMIC-III（後來 MIMIC-IV 擴至 40 萬重症紀錄）。一群麻省理工 / Harvard 學生做了「TREWScore 在 MIMIC-IV 上的 reproducibility audit」——AUROC 從原文的 0.83 掉到 0.61。原因：MIMIC 病人比原研究嚴重、抗生素時序記錄方式不同、ICU 文化差異。

這個「打臉」反而救活了 sepsis ML 領域——它示範了外部驗證 + 公開資料能糾正高調但脆弱的研究。後來 PhysioNet Computing in Cardiology 2019 Challenge（基於 MIMIC-IV + eICU 跨機構）成為 sepsis 預測模型的「必過關卡」，所有後續發表都要在這個 benchmark 上跑。

更重要的是：MIMIC-IV 是免費 + 開放（CITI training 後即可下載），讓全球低中收入國家學生也能參與。這是「公開資料民主化」的勝利。

In 2018, Henry et al. (Sci Transl Med) released TREWScore, claiming 28-hour-early sepsis prediction. But training was on a single hospital, 5 years; no external validation.

That year Beth Israel released MIMIC-III (later MIMIC-IV grew to 400K ICU records). MIT/Harvard students audited TREWScore on MIMIC-IV — AUROC dropped from 0.83 to 0.61. Reasons: MIMIC patients sicker, antibiotic timing recorded differently, distinct ICU culture.

The "exposure" rescued the sepsis-ML field — it demonstrated that external validation + open data can correct flashy but fragile studies. The PhysioNet Computing in Cardiology 2019 Challenge (cross-institution MIMIC-IV + eICU) became the "gate" for sepsis models — every paper now reports on it.

Bigger picture: MIMIC-IV is free + open (download after CITI training), letting LMIC students participate. This is open-data democratization winning.

教訓：「公開資料庫不只是燃料，它是同行評審的延伸——讓壞研究沒地方躲。」
Lesson: open databases aren't just fuel — they extend peer review, leaving bad research nowhere to hide.
迷思 vs 事實

五個常見誤會

① 合成資料能完全替代真實。
① 適合增廣與預訓，不適合最終評估。
Synthea 生成的患者軌跡缺乏罕見變異與真實噪音；MedGAN / TabDDPM 合成樣本在子群表現可能差 5–15 pp（Chen 2023 npj Digit Med）。FDA 2025 草案指引明確：合成資料可輔助但不能取代真實臨床效能評估。 Synthea-generated trajectories lack rare variants and real noise; MedGAN / TabDDPM samples often drop 5–15 pp on subgroup performance (Chen 2023 npj Digit Med). 2025 FDA draft: synthetic data can supplement but not replace real clinical efficacy.
② UKB 是世界級，所以代表全球。
② 94% 歐裔，PRS 在非歐裔誤差放大 4–5×。
Martin 2019 (Nat Genet) 證明 UKB-PRS 用在東亞、非裔群體的 R² 下降 50–70%。台灣讀者請先用 Taiwan Biobank (~22 萬) 或 BBJ (~26 萬) 訓練/驗證，UKB 只做泛化測試。 Martin 2019 (Nat Genet) showed PRS R² drops 50–70% on East Asian / African groups. Taiwanese readers: train/validate on Taiwan Biobank (~220K) or BBJ (~260K) first; use UKB only for generalization.
③ dbGaP access = 解鎖一切。
③ 每個資料集要單獨申請 DAR。
dbGaP 的 Data Access Request (DAR) 要逐 phs 編號送 NIH Data Access Committee；TCGA、TOPMed、All of Us 各自有 access committee；通過後資料用途也受 Consent Group 限制（GRU、DS-CC、HMB...）。 Each phs ID needs its own DAR through the NIH Data Access Committee; TCGA, TOPMed, All of Us have separate committees; use is restricted by Consent Group codes (GRU, DS-CC, HMB...).
④ 刪 18 項就是去識別化。
④ Safe Harbor 是底線，不是天花板。
Sweeney 1997 證明 87% 美國人口可由「郵遞區碼+生日+性別」重建身分；高維基因組或影像更嚴重（Gymrek 2013：1Mb 串列重複可定位姓氏）。建議搭配 k-anonymity / l-diversity / differential privacy。 Sweeney 1997 showed 87% of US population is re-identifiable from ZIP+DOB+sex; genomic and imaging data is worse (Gymrek 2013: STR can recover surname). Combine with k-anonymity / l-diversity / differential privacy.
⑤ HCA 50M 細胞已經足夠。
⑤ 病變/老化/跨族裔細胞仍不足。

想得更深

Q1. 資料平等性 (data equity)：LMIC 怎麼參與這場大數據競賽？ 全球 80% 的生醫資料在高收入國家。LMIC（Low- and Middle-Income Countries）很難自建 50 萬人世代——但 H3Africa、GenomeAsia 100K、MERIT-G、Mexico City Prospective Study 都在補位。 延伸：聯邦學習 (federated learning) 與差分隱私能讓 LMIC 「貢獻訓練但不交出資料」嗎？
Q1. Data equity: how can LMICs join the big-data race? 80% of global biomedical data sits in high-income countries. LMICs can't build their own 500K cohorts — but H3Africa, GenomeAsia 100K, MERIT-G, Mexico City Prospective Study are filling the gap. Extend: can federated learning + differential privacy let LMICs "contribute to training without surrendering data"?
Q2. 台灣 Biobank 的優勢與限制？ TWB ~22 萬人，東亞祖源代表性遠勝 UKB；但模態仍以基線 + 部分回訪為主，缺乏即時 EHR 連結（受限於健保資料規範）。能否與健保資料庫做合法串接，是台灣 AI 醫療的關鍵戰場。 參考：衛福部資料中心（HWDC）與 Taiwan AI Labs 在做的 federated approach。
Q2. Taiwan Biobank — strengths and limits? TWB ~220K, East-Asian representation far better than UKB; but modalities focus on baseline + partial follow-up, lacking real-time EHR linkage (limited by NHI data rules). Whether TWB can legally link to NHI is Taiwan's pivotal AI-medicine battleground. Reference: MOHW's HWDC and Taiwan AI Labs' federated approach.
Q3. 合成資料 (synthetic data)：到底是不是救星？ NVIDIA、Mostly AI、Synthea 都在推。優點：避免隱私法規、無限增廣、平衡子群。風險：合成器把訓練資料的 bias 也複製進去（"garbage in, glossy garbage out"）；FDA 2025 草案要求合成資料須做「fidelity + utility + privacy」三重評估。 辯論：synthetic data 可用於「pretraining」（OK 多數人同意），可用於「FDA submission 的 pivotal study」？（爭議大）
Q3. Is synthetic data the savior? NVIDIA, Mostly AI, Synthea all push it. Pros: bypass privacy law, infinite augmentation, balance subgroups. Risks: synthesizers replicate training bias ("garbage in, glossy garbage out"); FDA's 2025 draft requires triple evaluation — fidelity + utility + privacy. Debate: synthetic data for pretraining (most agree OK), for pivotal-study FDA submission (heavily contested).
Q4. TRE (Trusted Research Environment) 會殺死「我的本地 Jupyter」嗎？ UK Biobank-RAP、Genomics England、NIH STRIDES、Taiwan NCHC 都走 TRE 路線——資料不出 enclave，分析在雲端。優點：合規、可審計；缺點：vendor lock-in、運算費用、無法用本地 GPU。 行動：學會 DNAnexus / Terra / AWS Open Data；本地 vs 雲端混合工作流是未來。
Q4. Will TREs kill "my local Jupyter"? UKB-RAP, Genomics England, NIH STRIDES, Taiwan NCHC all go TRE — data stays in enclave, analysis in cloud. Pros: compliance, auditability. Cons: vendor lock-in, compute cost, no local GPU. Action: learn DNAnexus / Terra / AWS Open Data; hybrid local + cloud is the future.
Q5. 「擁有資料」vs「拜訪資料」哪個是未來？ FAIR + TRE 的趨勢是「資料留在原地、程式碼來訪問」。這需要 ML 工程師習慣「無法 ls 看完整檔案」的工作方式。 技術：dvc-fs、s3-mount、parquet partition pruning、SQL pushdown 都是必修技能。
Q5. "Own data" vs "visit data" — which is the future? FAIR + TRE points to "data stays put, code visits". ML engineers must adapt to "can't ls the full directory" workflows. Tech: dvc-fs, s3-mount, parquet partition pruning, SQL pushdown — all essential.
