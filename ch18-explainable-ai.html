可解釋 AI 與生醫應用

SHAP、Integrated Gradients、Grad-CAM、Concept Bottleneck、Counterfactuals——一張圖看懂。

SHAP, Integrated Gradients, Grad-CAM, concept bottlenecks, counterfactuals — in one diagram.

新手友善 中階 進階補充

這一章你會學到什麼？

從第一次聽到 SHAP的學生到已用過 Grad-CAM的工程師：

  • 分辨 SHAP / LIME / IG / Grad-CAM / Concept Bottleneck / Counterfactual 六大方法
  • 讀懂「attention ≠ explanation」的爭論
  • 知道何時用 deletion test、sanity check 量化解釋忠實度
  • 避開「視覺化 attribution map 就代表解釋」「attention 一定可信」迷思

From SHAP newcomers to Grad-CAM users:

  • Differentiate SHAP / LIME / IG / Grad-CAM / Concept Bottleneck / Counterfactual
  • Understand the "attention ≠ explanation" debate
  • Know when to use deletion test, sanity check to quantify faithfulness
  • Steer clear of "visualizing attribution = explanation" and "attention is trustworthy" myths
為什麼解釋

三個目的

(1) 除錯：模型是不是學到「scanner ID」而非疾病？(2) 建立信任：醫師能否認可 AI 的輸出？(3) 科學發現：高重要度特徵是不是新的生物標誌？這三者要求的解釋程度與方法不同。不要把所有解釋當「解釋」。

(1) Debugging: did the model learn the scanner ID instead of disease? (2) Trust: can clinicians endorse outputs? (3) Scientific discovery: are top features novel biomarkers? Each demands different methods and depth. Don't treat every explanation as "the explanation."

主流方法

六種你需要會的解釋方法

① SHAP

基於 Shapley 值的「公平特徵歸因」。KernelSHAP（model-agnostic）、TreeSHAP（XGBoost / RF 用，極快）、DeepSHAP。生醫 tabular / EHR 標配。

Fair feature attribution via Shapley. KernelSHAP (model-agnostic), TreeSHAP (XGB/RF, very fast), DeepSHAP. Staple for tabular / EHR.

② Integrated Gradients

從 baseline 到輸入，對梯度沿線積分。常見於影像、序列；具備「完整性 (completeness)」性質。

Integrate gradients from baseline to input. Common for image/sequence; satisfies completeness.

③ Grad-CAM

用最後一層 conv 的梯度加權產生 heatmap。胸 X 光、CT 的標準視覺化。

Weight last-conv feature maps by gradients to make heatmaps. Standard for chest X-ray / CT.

④ Attention / Probing

Transformer 直接出 attention，但「attention ≠ explanation」是 2024 共識；probing 比 attention 更可靠。

Transformer exposes attention, but "attention ≠ explanation" is 2024 consensus; probing is more reliable.

⑤ Concept Bottleneck Models

強迫模型先預測「人類可理解概念」（腫瘤大小、染色強度…），再從概念預測標籤。臨床最易接受。

Force the model to predict human-readable concepts first (size, stain intensity…), then map to labels. Most clinician-friendly.

⑥ Counterfactual / What-if

「如果 LDL 降到 100，預測會不會翻盤？」可操作性最強，但生成可靠的反事實仍困難。

"If LDL drops to 100, does the prediction flip?" Most actionable, but generating reliable counterfactuals is hard.

⚠️
2024 醫學影像 XAI 系統評論的警示：多數研究視覺化 attribution map 後就結束，沒有量化 faithfulness（解釋是否真實反映模型決策）。請至少加做 deletion / insertion test 或 sanity checks。 2024 XAI systematic-review warning: most studies stop at visualizing attribution maps without quantifying faithfulness. At minimum run deletion/insertion tests or sanity checks.

案例故事
2018 · Caruana 「Pneumonia 反事實」

「氣喘 → 肺炎風險低」的警世故事

1990 年代，Caruana 等人訓練了一個神經網路預測肺炎患者死亡風險，整體 AUC 高。後來他們訓練一個可解釋的廣義加性模型 (GA²M) 在同樣資料上做相同任務——發現一個荒謬的學習：「有氣喘病史 → 肺炎死亡風險較低」。

真相：氣喘患者一進 ER 就被優先送 ICU 並打強效抗生素，他們實際死亡率較低是治療的結果。神經網路把「我們會優先救治氣喘患者」誤學成「氣喘是肺炎的 protective factor」——若把這個模型導入決策，反而會不去優先救治氣喘患者，導致災難。

Caruana 2015 KDD 論文後，這個案例成為「為何 deep learning 必須有 explainability」的經典教材。啟示：不可解釋的高 AUC 模型 + 沒做反事實分析 = 隱形災難。當前 EU AI Act 把高風險 AI 的可解釋性列為強制條款，這個故事是直接驅動之一。

In the 1990s, Caruana et al. trained a neural network on pneumonia patient mortality with high AUC overall. They later trained an interpretable Generalized Additive Model (GA²M) on the same data — and found an absurd pattern: "history of asthma → LOWER pneumonia mortality risk".

The truth: asthma patients arriving at the ER are prioritized for ICU and strong antibiotics — their lower mortality is a treatment effect. The neural network learned "we prioritize asthma patients" as "asthma is protective for pneumonia". Deploying this model would deprioritize asthma patients — disastrous.

Caruana 2015 KDD paper made this the classic teaching case for "why deep learning needs explainability". Lesson: uninterpretable high-AUC model + no counterfactual analysis = invisible catastrophe. EU AI Act mandates explainability for high-risk AI; this story directly drove that requirement.

教訓：高 AUC ≠ 高臨床效益；不解釋的模型可能學到「治療效應」當「疾病風險」，反向決策會傷害病人。
Lesson: high AUC ≠ high clinical benefit; uninterpreted models may learn "treatment effects" as "disease risk", and reversing decisions harms patients.

想得更深

Q1. 解釋對臨床醫師真的有幫助嗎？Bansal 2021 顯示：對「常見任務 + 高表現 AI」，解釋反而降低醫師信任校準（醫師過度信任解釋）。對「罕見任務 + AI 不確定」解釋才真有效。參考：Lai et al. 2023 ACM FAccT對醫師-AI 協作的元評估。
Q1. Do explanations really help clinicians?Bansal 2021: for "common tasks + high-performing AI", explanations worsen trust calibration (over-trust). Explanations help only for "rare tasks + AI uncertainty".Reference: Lai et al. 2023 ACM FAccT meta-eval of clinician-AI collaboration.
Q2. EU AI Act 強制可解釋性會如何改變產業？2026-08 起高風險 AI 須提供「meaningful information about logic」。預期：(1) Concept Bottleneck Model 興起；(2) post-hoc SHAP / Grad-CAM 不夠，需要 inherently interpretable architecture；(3) audit 標準化。行動：學界投入「inherently interpretable foundation models」研究。
Q2. How will EU AI Act's interpretability mandate change industry?From 2026-08 high-risk AI must provide "meaningful information about logic". Expect: (1) Concept Bottleneck Models rise; (2) post-hoc SHAP/Grad-CAM insufficient — need inherently interpretable architectures; (3) standardized audits.Action: academia invests in "inherently interpretable foundation models".
Q3. SHAP 在大型 LLM 上還行得通嗎？計算 SHAP 對 billion-parameter LLM 太貴；常用 attention rollout、Integrated Gradients、或 logit lens 替代。但這些方法的忠實度仍存疑。前沿：Anthropic 2024 mechanistic interpretability for LLM internals。
Q3. Does SHAP work on huge LLMs?Computing SHAP for billion-parameter LLMs is too costly; alternatives: attention rollout, Integrated Gradients, logit lens. But their faithfulness remains contested.Frontier: Anthropic 2024 mechanistic interpretability for LLM internals.
Q4. 反事實解釋實務上多有用？對「actionable」決策（如「LDL 降到 100 預測會改變嗎」）極有用；對「不可改變」變數（性別、年齡）無意義。DiCE、Alibi 等工具已在金融、醫療部分情境落地。挑戰：生成「真實可行」的反事實仍困難。
Q4. How useful are counterfactual explanations in practice?Hugely useful for "actionable" decisions (e.g., "if LDL drops to 100, will the prediction change?"); meaningless for immutable variables (sex, age). DiCE, Alibi deployed in finance and some medical settings.Challenge: generating "realistic, feasible" counterfactuals remains hard.
常見問答
三條建議：(1) Tabular / XGBoost / RF—TreeSHAP（pip install shap，超快）；(2) 影像 CNN—Grad-CAM（pytorch-grad-cam）；(3) NLP / Transformer—Integrated Gradients (Captum)。永遠搭 deletion test 量化忠實度。Three picks: (1) Tabular / XGBoost / RF — TreeSHAP (pip install shap, very fast); (2) image CNN — Grad-CAM (pytorch-grad-cam); (3) NLP / Transformer — Integrated Gradients (Captum). Always pair with deletion test for faithfulness.
三標準：(1) Deletion test—依 attribution 高到低逐步遮蔽，畫 AUC drop curve；(2) Insertion test—從空白逐步加 attribution 高區，畫 AUC rise curve；(3) Sanity check—隨機化 model weights 後 attribution 應該變。三者皆過才能信。Three standards: (1) Deletion test — mask top-attribution features stepwise, plot AUC drop; (2) Insertion test — from blank, add top-attribution stepwise, plot AUC rise; (3) Sanity check — randomize model weights, attribution should change. Trust only after all three pass.
(1) 淺層 CNN—最後 conv 太小，heatmap 不夠精細；(2) Transformer 影像模型（ViT）—沒 conv，需 Grad-CAM++ 或 attention rollout；(3) 非分類任務—Grad-CAM 主要設計給 classification。對 segmentation 用 Score-CAM 或 LRP。(1) shallow CNN — last conv too small for fine heatmaps; (2) Transformer image models (ViT) — no conv, need Grad-CAM++ or attention rollout; (3) non-classification tasks — Grad-CAM is built for classification. For segmentation use Score-CAM or LRP.
